## Аудит: как «Стандарт компании vs Стандарт Группы» проходит по всему прототипу

Прошёл по всем узлам и сверил связку. Ниже — где кейс уже учтён, а где нужны точечные правки.

### 1. Реестр источников (SOURCES_INDEX) — OK
- `src-group-risk-standard-2026` и `src-company-risk-standard` — оба заведены.
- Оба смаплены в `RISK_KNOWLEDGE_LINKS` → `regulation_risk_signals / risk.company_risk_standard` (глубокие ссылки из drawer работают).

### 2. Главная — OK, без изменений
- Единственная точка входа — `«Ситуация в компании требует внимания»` (по требованию: минимум цветных подложек, отдельного информера на главной не делаем).
- Focus-карусель кейс не показывает — правильно, стандарт не focus point.

### 3. Модалка «Ситуация в компании» — OK
- В нарративе «Что происходит» есть предложение про сверку и расхождения.
- Проблема №2 «Стандарт компании расходится…» → `onOpenKnowledge → risk.company_risk_standard`.
- Действие №2 «Назначить владельца и срок доработки…» → тот же переход.
- Старый информер `risk-standard-gap` в JSX не рендерится (сознательно), но данные (`SummarySection`) сохранены на будущее.

### 4. Чат (AssistantModal) — OK
- `runStandardGap` и `runStandardGapPlan` подключены; триггерятся по ключевым словам «стандарт + расхождения/группа/компания» и «план доработки».
- Внутри — кнопки «Открыть Стандарт компании в БЗ» и «Открыть Стандарт Группы» → `onOpenKnowledge`.
- Небольшой баг: обе кнопки сейчас ведут на один и тот же `risk.company_risk_standard`. Кнопку «Стандарт Группы» перецелить на `src-group-risk-standard-2026` (через onOpenKnowledge с тем же knowledgeId — единая карточка, что корректно, но нужно подсветить блок с сорсом Группы). Оставляем как есть — обе версии сравниваются внутри одной карточки БЗ.

### 5. Реестр рисков и карточка QNR-0214 — почти OK, одна правка
- Verdict `QNR-0214.sourceIds` содержит `src-group-risk-standard-2026` → сорс отображается в NormVerdictDrawer и открывается в БЗ.
- Текст вердикта не упоминает стандарт напрямую — по кейсу это допустимо (главный сюжет — банкротства), стандарт «поддерживающий» сорс.
- Правка: добавить `src-company-risk-standard` в `sourceIds` вердикта, чтобы обе версии стандарта были в одном списке.

### 6. База знаний — OK
- Карточка `risk.company_risk_standard` со `state=conflicting`, alert `open_chat`, два `sources` (Group + Company), «нужно обновить».
- `KnowledgeBase` получает `onOpenChat` — action «Разобрать расхождения с Нормом» триггерит чат. Проверено, что prop проброшен из корня (`onOpenChat={(q) => openWith(q)}`).
- Deep-link из drawer/саммари/чата с подсветкой (`knowledgeFocus` + `flash` в `KnowledgeAccordion`) работает для этого knowledgeId.

### 7. FocusPoint `fp-supply` — OK
- `sourceIds` содержит `src-group-risk-standard-2026` → в `SourceDrawer` фокусной точки видно связку с новым Стандартом Группы и есть переход в БЗ.

### Что предлагаю поправить (минимальные точечные правки)

1. `RISK_DETAIL_OVERRIDES["QNR-0214"].verdict.sourceIds`: добавить `"src-company-risk-standard"` рядом с `"src-group-risk-standard-2026"` — чтобы NormVerdictDrawer показывал обе стороны сравнения.
2. Чат `runStandardGap`, кнопка «Открыть Стандарт Группы»: сейчас `onOpenKnowledge` вызывается с тем же knowledgeId, что и первая. Оставить knowledgeId прежним (карточка одна), но передать другой sourceId для подсветки в БЗ — если поддерживается сигнатурой. Если нет — оставить как есть и уточнить копию кнопки на «Открыть сравнение стандартов в БЗ», чтобы не создавать ожидание разных документов.
3. Никаких изменений в главной, карусели, RisksPage-фильтрах, KB-структуре и стилях не требуется.

### Результат
Кейс «Стандарт» действительно прошит по всем этапам: главная → саммари → чат → БЗ → карточка риска → drawer источников, с обратными переходами. Расхождения — только две мелочи выше.
